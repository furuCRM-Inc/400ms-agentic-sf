**ツイート 1／9（フック）**

---

**ツイート 2／9（問題の本質）**
```
今のAIエージェントが遅い理由は技術じゃなくて設計ミス。

❌ LLMに画面を「読ませて」
❌ 返答を1トークンずつ生成して
❌ DOMを探してボタンをクリック

これ、毎回20秒かかる。

顧客が怒っているリアルタイムチャットで20秒は永遠。
```

---

**ツイート 3／9（ビフォー）**
```
🐌 従来のAIエージェント

0ms    「返金しろ！」メッセージ受信
500ms  画面をスクリーンショット
2秒    LLMが画面を「読む」
5秒    返答を生成中…
8秒    ボタンの場所を推論
12秒   DOMを探してクリック
20秒   ✅ ようやく完了

この間に顧客は競合のサイトを開いている。
```

---

**ツイート 4／9（アフター）**
```
⚡ Jev + WebMCP

0ms   同じ「返金しろ！」メッセージ
50ms  判断完了（テキスト生成なし）
250ms 返金処理を直接実行
400ms ✅ 完了。謝罪メッセージ送信済み

担当者がメッセージを読み終わる前に終わっている。
```

---

**ツイート 5／9（Jev解説）**
```
Jevとは何か。

カーネマンの「ファスト&スロー」で言う System 1 AI。

LLM（System 2）→ じっくり考えて長文を生成
Jev（System 1）→ 50msで構造化JSONだけ出力

{ urgency: "CRITICAL",
  action: "APPROVE_MAX_REFUND",
  confidence: 0.97 }

エッセイじゃなく判断結果だけ。それだけでいい。
```

---

**ツイート 6／9（WebMCP解説）**
```
WebMCPとは何か。

従来：エージェントが画面を「見て」ボタンを探す
WebMCP：UIが自分をAIに直接宣言する

// Salesforce LWCのコード
document.modelContext.registerTool({
  name: "approve_refund",
  execute: async (args) =>
    ApexController.approveRefund(args)
});

スクリーンショット不要。DOM探索不要。壊れない。
```
