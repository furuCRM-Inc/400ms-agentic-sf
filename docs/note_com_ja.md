# ⚡ AIエージェントの「15秒の壁」を壊した話——Salesforceが400msで自律動作するまで

VIP顧客が激怒している。損失は$50,000。解約を要求している。

従来のAIエージェント：15〜20秒かけて「考え中…」
私たちのエージェント：**400ミリ秒で解決済み。**

今日はその仕組みと、ビフォー・アフターの差を正直に書く。

---

## なぜ今のAIエージェントはこんなに遅いのか

今のAIエージェントデモのほとんどは**構造的に遅い**。

画面をスクリーンショットで読んで、長い文章を生成して、ボタンを「見つけて」クリックして——そのたびに何秒も待たされる。顧客が怒り狂っているリアルタイムチャットで、エージェントが「考え中…」と表示している間、あなたのビジネスは燃えている。

これは技術の問題ではなく、**設計の問題**だ。

## ビフォー vs アフター

### 🐌 ビフォー（従来のLLMエージェント）

| 時刻 | 処理内容 |
|---|---|
| 0ms | 顧客「システムが落ちてる。$50,000の損失。今すぐ解約して返金しろ！」 |
| 500ms | エージェントがスクリーンショットを撮影 |
| 2,000ms | LLMがスクリーンを「読んで」状況を理解 |
| 5,000ms | LLMが返答文を1トークンずつ生成中…「お客様のご不満を…」 |
| 8,000ms | どのボタンをクリックすべきか「推論」 |
| 12,000ms | DOM要素を探してクリック試行（UI変更で失敗する可能性あり） |
| 15,000ms | ようやく返金処理開始 |
| **20,000ms** | **✅ 完了** |

**20秒。** 顧客はその間に解約ページを探し始めている。

| 時刻 | 処理内容 |

**0.4秒。** 担当者がメッセージを読み終わる前に解決している。

## 何が違うのか——2つの技術

### 技術①：Jev（System 1 AI）——「反射」で動くAI

ダニエル・カーネマンの「ファスト＆スロー」を知っているだろうか。

- **System 2（遅い思考）**：じっくり考える。従来のLLMがこれ。
- **System 1（速い思考）**：瞬間的な反射。Jevがこれ。

従来のLLMは怒り狂った顧客のメッセージを受け取ると、**小説を書くように**返答を生成し始める。

Jevは違う。テキストを一切生成しない。代わりに**50ミリ秒で構造化データだけを出力する**。

```json
{
  "urgency": "CRITICAL",
  "recommended_action": "APPROVE_MAX_REFUND",
  "route_to": "TIER_3_RETENTION",
  "confidence": 0.97,
  "threat_value": 50000,
  "sentiment_score": -0.94
}
```

エッセイではなく、**判断結果だけ**。これが欲しいのはこれだ。

---

### 技術②：WebMCP——「見る」のをやめて「呼ぶ」

ここが本質的な設計の違いだ。

**従来のエージェントがSalesforceを操作する方法：**

```
画面をスクリーンショット
    ↓
「返金ボタンはどこ？」とLLMに質問
    ↓
DOMを探索してボタンを見つける
    ↓
クリックシミュレーション
    ↓
（Salesforceのデザインが変わったら全部壊れる）
```

WebMCPはアプローチを逆転させる。

**UIコンポーネント自身がAIに「私はこう使える」と宣言する。**

```javascript
// Salesforce LWC側のコード
connectedCallback() {
    document.modelContext.registerTool({
        name: "approve_refund",
        description: "VIP顧客の返金を即時処理する",
        execute: async (args) => {
            return await VipRetentionController.approveRefund(args);
        }
    });
}
```

エージェントは**画面を見ない**。ツール名を呼ぶだけ。

スクリーンショット不要。DOM探索不要。UI変更に壊れない。

## 7項目の比較表

| 項目 | 従来のLLMエージェント | Jev + WebMCP |
|---|---|---|
| 判断速度 | 2〜8秒（トークン生成） | **50ms**（構造化出力） |
| UI操作 | スクリーンショット + DOM探索 | **直接ツール呼び出し** |
| UI変更への耐性 | 壊れやすい | **壊れない**（API設計） |
| 合計処理時間 | 15〜20秒 | **400ms** |
| 出力形式 | 自然言語（長文） | 構造化JSON |
| トークンコスト | 高い | **ほぼゼロ**（判断部分） |
| 失敗時の挙動 | リトライループ | 即時フォールバック |

## 「勝手に返金して大丈夫？」という疑問に答える

当然の疑問だ。

**答え：設計次第で完全に安全。**

WebMCPのツール登録はLWCコンポーネントが**明示的に行う**。

- どのツールが存在するか → 開発者が決める
- どの引数を受け付けるか → スキーマで定義
- 実際の処理 → 既存のApexセキュリティ（`with sharing`、FLS、プロファイル権限）に完全に従う

エージェントは新しい権限を一切持っていない。**既存のSalesforceセキュリティモデルの中でだけ動く**。
