## なぜ今のAIエージェントはこんなに遅いのか

正直に言う。

今のAIエージェントデモのほとんどは**詐欺的に遅い**。

画面をスクリーンショットで読んで、長い文章を生成して、ボタンを「見つけて」クリックして——そのたびに何秒も待たされる。顧客が怒り狂っているリアルタイムチャットで、エージェントが「考え中…」と表示している間、あなたのビジネスは燃えている。

私たちはそれを変えた。

## ビフォー vs アフター

### 🐌 ビフォー（従来のLLMエージェント）

```
t = 0ms     顧客「システムが落ちてる。$50,000の損失。今すぐ解約して返金しろ！」
            ↓
t = 500ms   エージェントがスクリーンショットを撮影（画面全体をキャプチャ）
            ↓
t = 2,000ms LLMがスクリーンを「読んで」状況を理解
            ↓
t = 5,000ms LLMが返答文を1トークンずつ生成中...「お客様のご不満を...」
            ↓
t = 8,000ms どのボタンをクリックすべきか「推論」
            ↓
t = 12,000ms DOM要素を探してクリック試行（UI変更で失敗する可能性あり）
            ↓
t = 15,000ms ようやく返金処理開始
            ↓
t = 20,000ms ✅ 完了
```

**20秒。** 顧客はその間に解約ページを探し始めている。

### ⚡ アフター（Jev + WebMCP）

```
t = 0ms     顧客「システムが落ちてる。$50,000の損失。今すぐ解約して返金しろ！」
            ↓
t = 50ms    Jevが構造化判断を出力（テキスト生成なし）
            ↓

            ↓
t = 350ms   担当チームへのルーティング完了
            ↓
t = 400ms   ✅ 完了。顧客に謝罪メッセージ送信済み。
```

**0.4秒。** 担当者がメッセージを読み終わる前に解決している。

## 何が違うのか——2つの技術

### 技術①：Jev（System 1 AI）——「反射」で動くAI

人間の思考には2種類ある（ダニエル・カーネマンの「ファスト＆スロー」）。

- **System 2（遅い思考）**：じっくり考える。LLMがこれ。
- **System 1（速い思考）**：瞬間的な反射。Jevがこれ。

従来のLLMは怒り狂った顧客のメッセージを受け取ると、**小説を書くように**返答を生成し始める。

Jevは違う。テキストを生成しない。代わりに**50ミリ秒で構造化データを出力する**。

```json
// Jevの出力（50ms）
{
  "urgency": "CRITICAL",
  "recommended_action": "APPROVE_MAX_REFUND",
  "route_to": "TIER_3_RETENTION",
  "confidence": 0.97,
  "threat_value": 50000,
  "sentiment_score": -0.94
}
```

エッセイではなく、**判断結果だけ**。それが欲しいのはこれだ。

---

### 技術②：WebMCP——「見る」のをやめて「呼ぶ」

ここが本質的な問題だ。

従来のエージェントがSalesforceを操作する方法：

```
画面をスクリーンショット
    ↓
「返金ボタンはどこ？」とLLMに質問
    ↓
DOMを探索してボタンを見つける
    ↓
クリックシミュレーション
    ↓
（Salesforceのデザインが変わったら全部壊れる）
```

これは**視覚障害者に目隠しをして手術させるようなもの**だ。

WebMCPはアプローチを逆転させる。

**UIコンポーネント自身がAIに「私はこう使える」と宣言する。**

```javascript
// Salesforce LWCのコード（コンポーネント側）
connectedCallback() {
    // UIが自分自身をAIツールとして登録する
    document.modelContext.registerTool({
        name: "approve_refund",
        description: "VIP顧客の返金を即時処理する",
        execute: async (args) => {
            // → Apexコントローラーを直接呼び出し
            return await VipRetentionController.approveRefund(args);
        }
    });
}
```

エージェントは**画面を見ない**。ツール名を呼ぶだけ。

```
// エージェントの動作（WebMCP）
approve_refund(amount=50000, caseId="VIP-001")  // これだけ。
```

スクリーンショット不要。DOM探索不要。UI変更に壊れない。

**状況：** VIP Enterprise顧客からライブチャットに着信。

> *「システムが落ちてる。$50,000の損失が出てる。今すぐ解約して全額返金しろ！」*

```

```

担当者がメッセージを読んでいる間に、エージェントはすでに動いていた。

## 「でも本当に安全なの？」という疑問に答える

当然の疑問だ。エージェントが勝手に返金処理していいのか？

**答え：設計次第。**

WebMCPのツール登録は**LWCコンポーネントが明示的に行う**。つまり：

- どのツールが存在するか → **開発者が決める**
- どの引数を受け付けるか → **スキーマで定義**
- 実際の処理 → **既存のApexセキュリティモデルに従う**（`with sharing`、FLS、プロファイル権限すべて有効）

エージェントは新しい権限を持っていない。**既存の権限の中でだけ動く**。

## これが「次のAIエージェント」の姿だと思う

私が信じるのは：

- LLMは「会話」に使う。**判断には使わない。**
- UIは「見られる」ためではなく、**「呼ばれる」ために設計する。**
- 速度は体験の一部だ。**400msと20秒では、顧客の感情が全く違う。**

Salesforceはすでにこの方向に動いている。Agentforce、Prompt Builder、Invocable Methodsがその証拠だ。

WebMCPはその最後のピース——**UIとエージェントの間のネイティブな接点**——を埋める。
